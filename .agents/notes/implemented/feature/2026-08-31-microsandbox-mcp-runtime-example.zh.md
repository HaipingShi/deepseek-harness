# Agent Note：Microsandbox MCP 运行时示例

状态：已实现

[English](2026-08-31-microsandbox-mcp-runtime-example.md) | 中文

## 问题

DSH 需要一条受限路径来获得硬件隔离的本地执行能力，同时不能把同进程沙箱策略误认为微虚拟机安全边界，也不能接管上游运行时的完整生命周期。宽松的 MCP 示例还可能默认暴露启动目录、允许模型安装运行时组件，或让使用者误以为关闭一个危险工具开关就授权了其余工具命名空间。

## 决策

在 `apps/cli/config/examples/mcp-sandbox` 下提供一个默认关闭的 stdio 覆盖层。它调用单独安装的 `microsandbox-mcp` 可执行文件，运维说明将其固定到 `0.6.16`；选择本地后端；要求 `DSH_MICROSANDBOX_HOST_PATHS`；将上游宿主路径策略固定为 `allowlist`；关闭危险工具开关；限制输出；设置显式操作与 MCP 调用超时；并在启动时响亮失败。

集成停留在通用 MCP seam。它不实现局部 `fs`、`subprocess` 或 `terminal` provider，因为这些角色必须共享生命周期、取消、投影和清理行为。它不选择云后端，也不传递凭据。它同样不声称上游开关或路径白名单会收窄发现的工具命名空间；部署通过 Agent 作用域限制或执行前策略作出该决定。

## 验证

无密钥应用测试解析仓库内覆盖层，检查准确的版本标记和安全环境变量，拒绝缺失的宿主路径白名单，用包自有 stdio MCP fixture 替换可执行文件，启动真实 Cordis Loader，并观察已发现工具。它不会安装 Microsandbox、启动微虚拟机、拉取镜像、运行 hypervisor 或证明宿主清理完成。

## 考虑过的替代方案

**实现新的核心 sandbox backend。** 已拒绝，因为现有 sandbox service 表达同一执行环境中的限制。微虚拟机包围文件系统、进程和终端能力，而不是只提供一种策略模式。

**先实现一个原生 provider。** 已拒绝，因为单独的文件系统或子进程 adapter 会让职责和生命周期分裂在不同执行环境中，也不构成完整的 capability seam。

**通过 `npx` 或 `pnpm dlx` 运行软件包。** 已拒绝，因为 Agent 启动会执行软件包解析、下载、生命周期脚本和变化中的依赖图。

**接受上游默认宿主路径。** 已拒绝，因为运维方遗漏安全相关选择时，它会静默暴露 DSH 启动目录。

## 后果

该示例不增加依赖，也不改变任何已发布 profile。运维方安装已审阅的可执行文件与运行时，选择可丢弃宿主路径，限制模型可见工具集，审阅镜像和网络访问，并在受支持宿主机上执行真实的创建—执行—清理 canary。未来的原生 provider 家族仍是独立工作。
